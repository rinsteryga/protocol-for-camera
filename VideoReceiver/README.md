# Архитектура VideoReceiver (Клиент трансляции)

Приложение реализует прослушивание UDP-порта, сборку фрагментированных кадров, декомпрессию данных и их рендеринг в реальном времени. Архитектура оптимизирована для работы в условиях потери пакетов и использует разделение сетевой и графической логики по потокам.

---

## Пайплайн данных (Data Flow)

1. **Transport**: `QUdpSocket` (Прием) -> `rawData`
2. **Validation**: `PacketData::fromQBA` (Хеш-сумма + Извлечение заголовка)
3. **Decompression**: `qUncompress` (Восстановление Payload)
4. **Assembly**: `FrameBuffer` (Сборка фрагментов по `frameId`)
5. **Rendering**: `QImage` -> `QmlImageItem` (Отрисовка в QML)

---

## 1. Протокол передачи данных (`Packet.hpp`)

Описывает логику извлечения данных из сети. Пакет состоит из открытого заголовка и сжатого тела.

### PacketHeader (Заголовок)
* Содержит метаданные: `type` (тип сообщения), `frameId` (ID кадра), `fragmentIdx` (номер части), `totalFragments` (всего частей) и `hash` (контрольная сумма).

### PacketData (Десериализация в `PacketData.cpp`)
* **`fromQBA()`**: 
    1. **Валидация**: Проверяет контрольную сумму `qChecksum` всего пришедшего массива. Если хеш не совпадает, пакет немедленно отбрасывается.
    2. **Извлечение**: Считывает структуру `PacketHeader` через `memcpy`.
    3. **Декомпрессия**: Выполняет `qUncompress` для остатка данных (`mid(sizeof(PacketHeader))`). Благодаря предварительному отсечению заголовка, `qUncompress` получает корректный zlib-поток с 4-байтным префиксом длины, что предотвращает ошибку "Corrupt Data".

---

## 2. Сетевое ядро

### ReceiverWorker (Сетевой поток / `QThread`)
Изолирует сетевой стек от UI-потока для обеспечения плавного воспроизведения.

* **Динамический Handshake**: При запуске или нажатии кнопки "Connect" отправляет UDP-пакет `MsgType::Request` на IP сервера. Это позволяет серверу узнать адрес клиента и начать трансляцию (актуально для VPN/NAT).
* **Прием данных**: Слушает порт `5555`. Буфер приема ОС увеличен до 8 МБ (`ReceiveBufferSizeSocketOption`) для минимизации потерь при высоком битрейте.
* **Сборка кадра (Lossy Assembly)**: 
    * Пакеты сохраняются в `std::map` или хэш-таблицу по ключу `frameId`.
    * При получении первого фрагмента нового кадра преаллоцируется буфер. 
    * Данные копируются строго по смещению: `fragmentIdx * CHUNK_SIZE`.
* **Обработка потерь (Drop Handling)**: Если приходит фрагмент от более нового `frameId`, текущая сборка старого кадра принудительно завершается. Недополученные фрагменты остаются "дырами" (черными пикселями), что позволяет избежать лагов и переполнения памяти.

## 3. Графический интерфейс и Рендеринг

### VideoReceiver (Менеджер интерфейса)
Служит мостом между C++ и QML.
* Принимает собранный и распакованный `QImage` из Worker-потока.
* Обновляет `Q_PROPERTY` и уведомляет QML-движок через систему сигналов/слотов.

### QmlImageItem (Кастомный рендер)
Наследуется от `QQuickPaintedItem` для прямого вывода `QImage` в граф сцены.
* **Производительность**: Обходит ограничения стандартного элемента `Image`, исключая лишнее копирование и использование временных файлов/URL.
* **Отрисовка**: Метод `paint()` выполняет масштабирование кадра (`Qt::KeepAspectRatio`) и отрисовку через `QPainter`, обеспечивая высокую частоту кадров (FPS) без мерцания.

---

## 4. Особенности реализации

* **Устойчивость**: Проверка хеша до распаковки гарантирует, что `qUncompress` не будет вызван на поврежденных данных, что исключает падение потока.
* **Гибкость**: Благодаря механизму Handshake, клиент может подключаться к серверу в любой момент, инициируя поток данных.
* **Память**: Использование `QByteArray::mid()` обеспечивает эффективную передачу срезов данных без лишнего глубокого копирования.
