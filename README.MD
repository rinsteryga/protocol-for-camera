# Архитектура VideoSender (Сервер трансляции)

Приложение реализует захват видеопотока с веб-камеры, его обработку, двухэтапное сжатие, фрагментацию и отправку по протоколу UDP. Архитектура адаптирована для работы в сложных сетях (NAT/VPN) через механизм динамического подтверждения (Handshake).

---

## Пайплайн данных (Data Flow)

1. **Capture**: `QVideoSink` (Camera) -> `QVideoFrame`
2. **Processing**: `QVideoFrame` -> `QImage` (JPEG Encoding)
3. **Compression**: `QImage` -> `qCompress` (zlib Payload)
4. **Transport**: `PacketData` (Header + Data) -> `QUdpSocket` (UDP)

---

## 1. Протокол передачи данных (`Packet.hpp`)

Описывает структуру датаграмм. Пакет разделен на **фиксированный заголовок** (открытый вид) и **сжатую полезную нагрузку** (zlib).

### PacketHeader (Заголовок ~20 байт)
* `type` (`MsgType`): Тип сообщения (`Request`, `VideoFrame`).
* `frameId` (`quint32`): Глобальный инкрементальный идентификатор кадра.
* `fragmentIdx` / `totalFragments` (`quint16`): Индексы для корректной сборки кадра на стороне клиента.
* `hash` (`quint16`): Контрольная сумма **всего** сформированного пакета (`qChecksum`).

### PacketData (Сериализация в `PacketData.cpp`)
* **`toQBA()`**: 
    1. Выполняет `qCompress` только для массива `payload`.
    2. Формирует финальный массив: `[Header] + [Compressed Payload]`.
    3. Вычисляет хеш от всего «бутерброда» и записывает его в заголовок.
* **`fromQBA()`**: 
    1. Проверяет хеш пришедшего массива `rawData`.
    2. Извлекает заголовок через `std::memcpy`.
    3. **Важно:** Отсекает заголовок через `mid(sizeof(PacketHeader))` и передает в `qUncompress` только «чистый» zlib-поток. Это предотвращает ошибку коррупции данных из-за смещения.

## 2. Логика приложения

### VideoSender (GUI-поток)
* **Управление**: Использует `QMediaCaptureSession` и `QVideoSink`. Позволяет динамически выбирать камеру из списка `QMediaDevices`.
* **Подготовка**: Конвертирует кадр в `QImage`, выполняет Downscale и сохраняет в `QByteArray` с использованием **JPEG-сжатия**.

### SenderWorker (Сетевой поток / `QThread`)
Изолирует сетевые операции, предотвращая фризы интерфейса.
* **Динамический Handshake**: Сервер слушает порт `5555` на всех интерфейсах (`AnyIPv4`). Трансляция начинается только после получения пакета `Request`. 
* **Auto-Discovery**: Адрес и порт клиента определяются «на лету» через `senderAddress()`, что обеспечивает работу через Radmin VPN и NAT без ручного ввода IP.
* **Вторичное сжатие**: Применяет `qCompress` к JPEG-данным, что позволяет эффективнее упаковывать данные в UDP-пакеты.
* **Фрагментация**: Нарезает данные на чанки по 1000–1400 байт (MTU-friendly).

---

## 3. Особенности сетевого взаимодействия

* **Целостность**: Использование `qChecksum` позволяет отбрасывать битые пакеты до попытки распаковки, защищая `qUncompress` от критических ошибок.
* **Оптимизация**: Установлен `SendBufferSizeSocketOption` (8 МБ) для минимизации потерь при всплесках трафика.
* **Кросс-интерфейсность**: Поддержка любых активных адаптеров (Ethernet, Wi-Fi, VPN) благодаря бинду на `AnyIPv4`.

## 4. Пользовательский интерфейс (QML)
* `VideoOutput`: Локальное превью для контроля ракурса.
* `ComboBox`: Селектор доступных камер.
* `Status Indicator`: Отображение состояния трансляции (Waiting/Active).
